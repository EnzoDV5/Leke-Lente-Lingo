## About The Project

> **“Skep woorde. Gee jou gunstelinge ’n stem. Versamel jou posters.”**

**Lente Book** is the interactive website behind **Leke Lente Lingo**, a participatory language campaign created for **Lentedag 2026**.

Instead of asking festivalgoers to simply consume campaign content, Lente Book turns the festival itself into a collaborative language experiment.

Across the Lentedag grounds, physical boards and standalone posters present familiar South African festival moments that do not necessarily have one perfect word.

Festivalgoers scan the QR code, enter the digital experience and create the word themselves.

The words can then be:

- ✍️ invented
- ✂️ remixed
- 👀 guessed
- 📸 photographed
- 🫂 challenged between friends
- 👍 voted on
- 🃏 collected through Lente Bingo

The strongest words rise through the live **Woord-Podium**, while the complete collection becomes part of the living Lente Book.

<p align="right">(<a href="#readme-top">▲ back to top</a>)</p>


### The Idea

Leke Lente Lingo asks a simple question:

> **What do you call something when the perfect word for it does not exist yet?**

Lentedag already has its own behaviour, jokes, characters, sounds, queues, friendships, mishaps and memories.

Lente Book gives those moments somewhere to live.

The physical posters create discovery around the festival grounds, while the website gives every participant a way to respond.

The result is a campaign that does not simply speak **to** the audience.

It lets the audience create the campaign language themselves.


### The Core Loop

```text
SEE A FESTIVAL MOMENT
        ↓
FIND / SCAN A POSTER
        ↓
OPEN LENTE BOOK
        ↓
CREATE / REMIX / GUESS / VOTE
        ↓
COLLECT THE POSTER
        ↓
BUILD YOUR LENTE BINGO
        ↓
WORDS ENTER THE LIVE COMMUNITY
        ↓
THE CROWD DECIDES WHAT SURVIVES
```

The interaction moves continuously between the **physical festival** and the **digital platform**.

That relationship is the core of the project.


### Three Campaign Phases

Lente Book does not exist as one static website.

The campaign changes depending on when the user visits.

| Phase | Purpose | Experience |
|---|---|---|
| 🌤 **Pre-Campaign** | Build anticipation | Introduces selected phrases and begins the language conversation before Lentedag |
| 🎪 **Live · Lentedag** | Main festival experience | QR scanning, word creation, voting, Lente Bingo, photographs, rankings and challenges |
| 🏆 **Post-Campaign** | Preserve the result | Highlights the words, winners and content created during the festival |

All three experiences run from the same Firebase-hosted project and can be previewed using the `?phase=` query parameter.


### Language & Culture

Leke Lente Lingo is built around the idea that language is not fixed.

It grows when people use it.

For the 2026 experience, Afrikaans is central to many of the word-building challenges, while the wider Lente Book concept celebrates **South African language and expression**.

The identity itself plays with different ways of saying **book**:

```text
Book
Boek
Buka
Incwadi
```

The project treats language as something social, playful and constantly changing rather than something that only lives in a formal dictionary.

## Experience

The application is divided into different screens rather than one long static campaign page.

Each screen has a specific role in the festival journey.


### 01 · Onboarding

**Route:** `/welkom`

The onboarding experience introduces Lente Book before the user enters the festival platform.

Users:

- discover the basic rules
- move through the onboarding steps
- choose a pixel avatar
- create a unique username
- receive a persistent anonymous Firebase identity

The profile becomes the user's identity across word submissions, voting, poster collection and friend challenges.


### 02 · Festival Home

**Route:** `/`

The home screen acts as the campaign hub.

During the live phase it brings together:

- festival photography
- live word activity
- campaign branding
- the Woord-Podium
- Lente Bingo progress
- information about the campaign
- navigation into challenges and the Woordeboek

The visual language deliberately carries the same clouds, colours, stickers, collage photography and hand-made campaign elements used on the physical festival material.


### 03 · Die Woord-Podium

The **Woord-Podium** turns language creation into a live festival competition.

Users can see:

- 🥇 leading words
- 👤 creators
- 🪙 score totals
- 👍 community votes
- 📊 statistics
- 🏆 top-ranked contributions

This makes the language generated during the day visible to everyone instead of hiding submissions inside a database.


### 04 · Lente Bingo

**Route:** `/collections`

Lente Bingo converts the QR poster system into a collectible experience.

Each scanned poster becomes part of the user's collection.

The interface shows:

- collected posters
- missing posters
- poster progress
- challenge progress
- locked Wildcard status
- direct links back into relevant challenges

The final Wildcard only unlocks after the main challenge posters have been collected.


### 05 · Die Woordeboek

**Route:** `/woordeboek`

The Woordeboek is the growing dictionary produced by the campaign.

It contains words created by festivalgoers and groups them around different festival moments and locations.

Users can explore the language that the crowd has created instead of only seeing their own submission.

Individual phrases also have dedicated routes:

```text
/woordeboek/:id
```


### 06 · Photo Wall

**Route:** `/foto`

Festivalgoers can capture a real Lentedag moment and give it a new word.

The application:

1. accepts the image
2. compresses it in the browser
3. attaches the user's word and profile
4. stores the uploaded media
5. creates a branded shareable Leke Lente Lingo image

The same feature is also available as a QR challenge:

```text
/challenge/foto
```

## Physical + Digital Campaign

Lente Book is designed to work **with the physical festival environment**, not replace it.

The real-world posters are the entry points.

```text
PHYSICAL BOARD
      ↓
QR CODE
      ↓
LENTE BOOK
      ↓
DIGITAL CHALLENGE
      ↓
USER CONTRIBUTION
      ↓
LIVE COMMUNITY RESULT
```

The campaign therefore connects environmental graphic design, interaction design and web development into one system.


## The Four Festival Boards

Four larger boards are placed at different areas around Lentedag.

Each area has its own visual identity and its own festival context.

| Board | Festival Area | Purpose |
|---|---|---|
| 🚽 **Die Poep Pods** | Porta-loo area | Language inspired by the festival bathroom experience |
| 🔊 **Die Beats Blok** | Stage + sound zone | Language inspired by music, crowds and live performances |
| 💨 **Die Choef-hoek** | Smoking / vape area | Language inspired by the social smoking corner |
| 🍻 **Die Dopstop** | Drinks + bar area | Language inspired by the bar and drinking experience |

Each board supports two key behaviours:

### ✏️ Doop Dit / Merk Dit

Create a new word for the scenario.

### ✂️ Steel & Verbeter

Take an existing word and make it better.

The same system is repeated across different festival locations so the interaction becomes familiar while the content changes.

## Poster Challenges

Lente Bingo contains **six core challenge posters** plus one locked **Wildcard**.

| # | Challenge | What the user does | Route |
|---:|---|---|---|
| 01 | ✏️ **Merk Dit** | Invent a new Afrikaans word for a festival phrase | `/challenge/doop/:phraseId` |
| 02 | ✂️ **Steel & Verbeter** | Remix somebody else's word | `/challenge/remix/:phraseId` |
| 03 | 👀 **Raai die Lingo** | Guess which scenario a word belongs to | `/challenge/raai` |
| 04 | 📸 **Kiekie die Oomblik** | Photograph a moment and give it a word | `/challenge/foto` |
| 05 | 📲 **Challenge ’n Chommie** | Send a language challenge to a friend | `/challenge/maat` |
| 06 | 👍 **Stem** | Vote for the words that should win | `/challenge/stem` |
| 07 | ⚡ **Die Wildcard** | Create your own scenario and your own word | `/challenge/wildcard` |

The Wildcard remains locked until the core collection is completed.

### Routing

React Router handles the different campaign and challenge screens.

```text
/welkom
/
/woordeboek
/woordeboek/:id
/collections
/foto

/scan/:challengeId

/challenge/doop/:phraseId
/challenge/remix/:phraseId
/challenge/raai
/challenge/stem
/challenge/foto
/challenge/maat
/challenge/maat/invite/:inviteId
/challenge/wildcard
```

Most feature screens are **lazy-loaded** so the initial entry experience stays lighter.

The onboarding screen and QR scan handler remain directly available because they are important entry points into the campaign.


### Firebase & Data

Firebase acts as the live data layer behind the festival.

Main collections include:

| Collection | Purpose |
|---|---|
| `settings` | Stores campaign state such as the active phase |
| `users` | User profiles and onboarding information |
| `usernames` | Unique username reservations |
| `phrases` | Official campaign phrases |
| `posters` | Official QR poster definitions |
| `words` | User-created and remixed words |
| `votes` | Individual user votes |
| `photos` | Festival photo-wall submissions |
| `friendInvites` | Challenge ’n Chommie invitations |
| `customPhrases` | User-created Wildcard scenarios |
| `stats` | Read-only campaign totals |

Individual poster progress is stored beneath each user:

```text
users/{userId}/posters/{posterId}
```


### Key Technical Patterns

<details>
<summary><strong>🎪 Three Campaign Modes</strong></summary>

<br />

`CampaignProvider` controls whether the site is currently showing:

```text
pre
live
post
```

The normal campaign phase can be read from Firestore.

For portfolio and demonstration purposes, a query parameter can temporarily pin the experience:

```text
?phase=pre
?phase=live
?phase=post
```

This allows all three campaign states to remain viewable even when the real event is in another phase.

</details>


<details>
<summary><strong>👤 Persistent Anonymous Authentication</strong></summary>

<br />

Festival users do not need a traditional email-and-password account.

Firebase Anonymous Authentication creates a hidden identity after onboarding is completed.

The application then stores:

```text
UID
username
avatar / character
onboarding status
```

This identity connects the user's submissions, votes and collected posters without introducing a heavy registration flow.

</details>


<details>
<summary><strong>📴 Firestore Offline Persistence</strong></summary>

<br />

Festival internet connections can be unreliable.

Firestore is initialised with a persistent local cache and multi-tab support.

This means pending festival actions can remain on the device and synchronise with Firebase when connectivity becomes available again.

</details>


<details>
<summary><strong>🔐 Unique Username Reservations</strong></summary>

<br />

Usernames are normalised before being saved.

A Firestore transaction reserves each username so two users cannot claim the same name simultaneously.

This gives each anonymous profile a recognisable festival identity without requiring a full login system.

</details>


<details>
<summary><strong>📱 Protected Festival Routes</strong></summary>

<br />

Core campaign pages are wrapped in `ProtectedRoute`.

Users are guided through onboarding before accessing their personal festival experience.

This ensures poster progress, votes and collections always belong to a stable user profile.

</details>


<details>
<summary><strong>📷 Browser-Side Image Compression</strong></summary>

<br />

Images selected for the Photo Wall are resized and compressed in the browser before upload.

This reduces the amount of data sent over the network — particularly useful in a busy festival environment.

Images can be converted into compressed WebP or JPEG files before being stored in Firebase Storage.

</details>


<details>
<summary><strong>🖼 Branded Social Share Images</strong></summary>

<br />

The application can generate branded Leke Lente Lingo images using the browser Canvas API.

The final share artwork combines:

- the user's photo
- campaign framing
- paper grain
- the submitted word
- username
- avatar

This transforms a normal festival upload into content that still carries the campaign identity when shared outside the website.

</details>


<details>
<summary><strong>📲 Challenge ’n Chommie</strong></summary>

<br />

Users can generate a challenge for another person.

Friend challenge records are stored in Firestore and can be opened through a dedicated invite route:

```text
/challenge/maat/invite/:inviteId
```

The invited user responds with a word and both sides can receive challenge progress.

</details>


<details>
<summary><strong>🎨 CSS-First Campaign Design System</strong></summary>

<br />

The main theme is defined inside:

```text
src/styles/index.css
```

Tailwind CSS v4 is used with CSS-first theme tokens rather than a traditional `tailwind.config.js`.

Campaign colours include:

```css
--color-teal:     #2FADA6;
--color-oranje:   #E8432B;
--color-pienk:    #E2127E;
--color-sagpienk: #F4A8CE;
--color-geel:     #F2C230;
--color-goud:     #EDA61A;
--color-groen:    #279E52;
--color-blou:     #2857C9;
--color-pers:     #7828B8;
```

The interface combines these global tokens with **CSS Modules** for feature-specific layouts.

</details>


<details>
<summary><strong>✨ Motion & Physics</strong></summary>

<br />

The project includes:

- **GSAP** for animated text behaviour
- **Matter.js** for physics-based falling campaign text
- CSS View Transitions
- reduced-motion fallbacks
- responsive interaction states

These techniques help the digital experience feel as energetic as the festival identity.

</details>

```bash
git clone https://github.com/EnzoDV5/Leke-Lente-Lingo.git
```

```bash
cd Leke-Lente-Lingo/lente-book
```

```bash
npm install
```

```bash
npm run dev
```

```text
http://localhost:5173
```

```text
Leke-Lente-Lingo/lente-book/
```

## Known Limitations

Lente Book was designed around a live festival environment, so several practical considerations are important.

- 📶 **Festival connectivity** — weak mobile reception can delay real-time synchronisation, although Firestore persistence helps protect pending activity.
- 📸 **Camera permissions** — QR and photo features depend on browser camera/file permissions.
- 🔐 **Browser storage** — the anonymous user identity relies on persistent browser storage; strict private-browsing settings may prevent it from persisting correctly.
- 🔥 **Firebase dependency** — live words, votes, profiles, photographs and poster progress require the configured Firebase project.
- 📱 **Mobile-first interactions** — many core festival actions are intentionally designed around phone use because users access them by scanning physical QR codes.
- 🎪 **Campaign-phase override** — `?phase=pre`, `?phase=live` and `?phase=post` are demonstration overrides used to preview all campaign states.
- 🖼️ **User-generated media** — uploaded festival photographs require appropriate moderation and media consent processes for a public production campaign.
